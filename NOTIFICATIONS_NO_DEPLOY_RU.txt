WEATHER PRO — УВЕДОМЛЕНИЯ БЕЗ CLOUD FUNCTIONS И ПЛАТНОГО ДЕПЛОЯ

Что работает в этой версии
--------------------------
1. Новые личные сообщения отслеживаются через существующие Firestore-чаты в реальном времени.
2. Красный счётчик сообщений считается по сообщениям после последней отметки прочтения.
3. Состояние прочтения каждого чата хранится локально на устройстве; при наличии разрешающих Firestore Rules оно дополнительно синхронизируется в users/{uid}.chatReads.
4. Центр уведомлений показывает новые сообщения, новые заявки в друзья и принятие заявок.
5. Для счётчика сообщений используются реальные сообщения Firestore; курсор прочтения надёжно сохраняется локально, а облачная синхронизация выполняется как необязательное дополнение. История уведомлений хранится на устройстве в браузере.
6. При разрешении браузера системные уведомления показываются, пока сайт открыт или продолжает работать в фоновой вкладке.
7. Существующие Firebase Auth, Firestore, GitHub Pages, личные чаты и Service Worker сохранены.

Установка
---------
1. Распакуйте архив.
2. Скопируйте все файлы из архива в корень существующего репозитория GitHub Pages, заменив старые файлы.
3. Опубликуйте изменения обычным способом через GitHub.
4. Откройте Weather Pro по HTTPS, обновите страницу и войдите в аккаунт.
5. Откройте раздел «Уведомления» и нажмите «Включить уведомления».
6. Разрешите уведомления в Android/Chrome.

Никакие команды npm, Firebase Functions, Cloud Functions, Blaze, Cloudflare или firebase deploy для этой версии не нужны.

Важно об ограничении браузера
-----------------------------
Это версия без серверного отправителя. Она получает сообщения и события через Firestore, пока сайт открыт или браузер продолжает выполнять страницу в фоне. Если полностью закрыть сайт/браузер или Android остановит его процесс, браузер не сможет получить новое событие и показать уведомление.

Для настоящего Web Push, который приходит даже после полного закрытия сайта, технически необходим внешний сервер-отправитель (например, Firebase Functions или Cloudflare Worker). Только HTML/JavaScript на GitHub Pages не может отправить push сам себе.

Приватный VAPID-ключ в этой версии нигде не используется и не включён в клиентские файлы. Вставлять закрытый ключ в index.html или Service Worker бесполезно и небезопасно.

Хранение
--------
- Чаты и сообщения остаются в текущих Firestore-путях chats/{chatId}/messages/{messageId}.
- Последняя отметка прочтения для каждого диалога хранится в users/{uid}.chatReads.
- Локальные уведомления и их read-состояние хранятся в localStorage этого браузера. Они не синхронизируются между устройствами.
- Подколлекция users/{uid}/notifications в этой версии не запрашивается: без серверного отправителя её документы не создаются, а чтение закрыто действующими правилами Firestore. Это предотвращает ошибку «Не удалось обновить уведомления».

Если счётчик прочтения не обновляется
--------------------------------------
Проверьте, что действующие Firestore Rules разрешают владельцу чтение и обновление собственного документа users/{uid}. В исходной схеме Weather Pro это уже разрешено для авторизованного пользователя при сохранении корректного profile.email.
