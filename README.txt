WEATHER PRO 10.1.2 — ACCOUNT & AUTH FIX

Основа: Weather Pro 10.1.1 Smart Device Ultimate. Сохранены погодные модули, Radar, AI Forecast, уведомления, PWA, Firebase, профиль с защищённым email, Device Engine MAX, локальный Device Monitor, новые Smart Device модули и исправление прокрутки Data Engine.

ИСПРАВЛЕНИЯ АВТОРИЗАЦИИ 10.1.2:
- Добавлен полноценный вход по email и паролю через Firebase Authentication.
- Добавлена регистрация по email и паролю с именем и повтором пароля.
- Email нормализуется (обрезка пробелов и нижний регистр), формат адреса проверяется до запроса.
- Пароль проверяется на минимальную длину 6 символов и совпадение подтверждения.
- Если почта уже зарегистрирована, показывается понятное сообщение «Эта почта уже зарегистрирована», экран автоматически переключается на вход, email подставляется в форму входа.
- Учтён конфликт, когда email уже занят другим способом входа (например, Google): предлагается войти тем способом, которым создан аккаунт.
- Добавлено восстановление пароля через письмо Firebase.
- Вход по Google сохранён.
- После успешной авторизации Firebase UID становится активной идентичностью Weather Pro; профильный экран и статус аккаунта обновляются, данные профиля загружаются из users/{uid}.
- Ошибка чтения Firestore больше не должна отменять сам факт входа или оставлять пользователя в гостевом состоянии: аккаунт активируется, а ошибка облачной загрузки показывается отдельно.
- Сводка профиля синхронизируется после изменения Firebase Auth-сессии.

ВАЖНО — НАСТРОЙКА FIREBASE:
1. Откройте Firebase Console → Authentication → Sign-in method.
2. Включите провайдер Email/Password (Email link не обязателен).
3. Убедитесь, что Google provider включён, если нужен вход через Google.
4. В Authentication → Settings → Authorized domains добавьте домен, на котором опубликован сайт.
5. Firestore Rules должны быть опубликованы из приложенного rules.txt. Они проверяют, что email в профиле совпадает с email из Firebase Auth token.

Если Email/Password не включён в Firebase Console, регистрация и вход по почте вернут объяснение, как включить провайдер. Уже зарегистрированный email нельзя зарегистрировать повторно; для него нужно войти через существующий способ.

ПРИВАТНОСТЬ:
Email в основном профиле остаётся только для чтения и берётся из Firebase Auth. Пароль никогда не сохраняется в localStorage или Firestore. Сброс пароля выполняется самим Firebase через письмо. Новые данные Device Engine и Smart Device остаются локальными, если пользователь отдельно не выполняет экспорт.

ПРОВЕРКИ ЭТОЙ СБОРКИ:
- JavaScript синтаксис проверен Node.js.
- Проверены уникальность HTML ID и наличие полей/обработчиков входа и регистрации.
- ZIP архив проверен на целостность.
- Реальная регистрация/авторизация и production Firestore не проверялись с подключением к проекту Firebase; для работы Email/Password провайдер нужно включить в Firebase Console.

ДОПОЛНЕНИЕ GOOGLE AUTH FIX 2 (10.1.2)

- Сохранён весь функционал 10.1.2: Email/Password, регистрация, обработка занятой почты, сброс пароля, профиль, Firebase, Device Engine, PWA и остальные разделы.
- Ключевое исправление: Google popup запускается непосредственно из обработчика нажатия, без предварительного асинхронного setPersistence(). Это сохраняет пользовательское действие браузера на Android и десктопе.

- Добавлена отдельная обработка unauthorized-domain, выключенного Google provider, popup-blocked, account-exists-with-different-credential, webview и сетевых ошибок.
- Во встроенных браузерах, где Google запрещает OAuth, выводится рекомендация открыть ссылку в Chrome.
- Обновлён Service Worker cache key.

Проверки: Node.js syntax check всех inline JS, повторяющиеся HTML ID, обязательные модули и email/password флоу, ZIP integrity. Реальный OAuth вход в Firebase-проекте не может быть завершён из среды сборки.
