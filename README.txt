WEATHER PRO V16.2.2 — STATIC WEB EDITION (NO NODE.JS)
====================================================

Это чистый веб-проект. В архиве нет Node.js-сервера, Cloud Functions,
package.json, npm-зависимостей или папки node_modules. Для размещения сайта
достаточно статического HTTPS-хостинга (например, GitHub Pages).

СОХРАНЁННЫЙ ВЕБ-ФУНКЦИОНАЛ
-------------------------
- Текущая погода, прогноз, избранные города, сравнение и история.
- Leaflet-карта, погодные слои, RainViewer-радар, 3D-карта и 3D-глобус.
- Weather AI через прямой браузерный запрос к Pollinations.
- Firebase Authentication (Google и Email/Password), профиль, друзья и чаты.
- Firestore, Data Engine, Device Engine в браузере, PWA, Service Worker,
  адаптивная веб-версия, темы и настройки.
- Клиентские уведомления и отслеживание непрочитанных сообщений, пока сайт
  открыт или работает во вкладке браузера.

АРХИТЕКТУРА
-----------
- index.html — основное веб-приложение.
- legacy-modules__*.js — JavaScript-модули приложения.
- v16-config.js, v16-core.js, v16-enhancements.js, v16-ui.css — код V16.
- 3d-satellite-hybrid-map.html — отдельная веб-карта.
- push-notifications.js / push-notifications.css — клиентские уведомления.
- sw.js и manifest.webmanifest — PWA и Service Worker.
- rules.txt и firestore.indexes.json — правила и индексы Firestore.
- firebase.json — только конфигурация Firestore для Firebase CLI; это не сервер
  и не требуется для запуска сайта на статическом хостинге.

FIREBASE
--------
Firebase Auth и Firestore используются из браузера через Firebase Web SDK.
Node.js для их работы в опубликованном сайте не нужен. Укажите настройки своего
Firebase-проекта в существующем клиентском конфиге приложения и добавьте домен
сайта в Firebase Authentication → Authorized domains. Правила Firestore находятся
в rules.txt.

WEATHER AI
----------
AI отправляет запрос непосредственно из браузера к Pollinations. Серверная
Cloud Function и серверная квота запросов удалены. Доступность AI зависит от
внешнего провайдера и его текущих правил доступа.

УВЕДОМЛЕНИЯ
-----------
Клиентские уведомления и индикаторы непрочитанных чатов сохранены. Автоматическая
серверная отправка FCM при новом сообщении удалена вместе с Cloud Functions.
Для доставки уведомлений о новых сообщениях после полного закрытия сайта нужен
отдельный push-сервис; в этом архиве серверной части нет.

ПУБЛИКАЦИЯ
----------
1. Распакуйте архив.
2. Загрузите все файлы из корня архива в корень GitHub-репозитория.
3. В GitHub включите Settings → Pages → Deploy from a branch, выберите main и /(root).
4. Откройте сайт по HTTPS. HTTPS необходим для полноценной работы Service Worker,
   PWA, геолокации и браузерных уведомлений.

Для запуска опубликованного сайта не нужны Node.js, npm, сборка или сервер.
V17.1.1: Исправлено скрытие значка основателя для не-владельцев. IP-адреса доступны в админ-панели только из реальных CSV-журналов хостинга; статический браузерный сайт не собирает IP других посетителей автоматически.
