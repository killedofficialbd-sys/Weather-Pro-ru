WEATHER PRO V17.1 — STATIC WEB / OWNER ADMIN CONSOLE / NO NODE.JS
=============================================

Чистая веб-сборка без Node.js и серверной части. Все файлы находятся в корне
архива, без вложенных каталогов. Нет package.json, npm-зависимостей и Cloud Functions.

ПУБЛИКАЦИЯ НА GITHUB PAGES
--------------------------
1. Распакуйте архив.
2. Загрузите все файлы из архива в корень GitHub-репозитория.
3. Откройте Settings → Pages → Deploy from a branch.
4. Выберите ветку main и каталог /(root), затем сохраните.
5. Откройте опубликованный адрес по HTTPS.

СОДЕРЖИМОЕ
----------
- index.html — главная страница сайта.
- 3d-satellite-hybrid-map.html — отдельная страница 3D-карты.
- legacy-modules__*.js — JavaScript-ядро приложения.
- v16-config.js, v16-core.js, v16-enhancements.js, v16-ui.css — код V16.
- push-notifications.js / push-notifications.css — клиентские уведомления.
- sw.js, manifest.webmanifest и weather-icon-* — PWA и веб-иконки.
- rules.txt, firestore.indexes.json, firebase.json — настройки Firestore.
- CHANGELOG-файлы — история версий.

FIREBASE И AI
-------------
Firebase Authentication и Firestore продолжают работать через веб-SDK браузера.
Node.js не нужен для запуска сайта. Настройте собственный Firebase-проект,
Authorized domains и правила Firestore из rules.txt.

Weather AI выполняет прямой запрос из браузера к Pollinations. Cloud Functions
удалены; серверной квоты AI и автоматической серверной отправки FCM для новых
сообщений в этой сборке нет. Клиентские уведомления и счётчики непрочитанных
сообщений сохранены.

ВАЖНО
-----
- Сайт можно разместить на GitHub Pages или другом статическом HTTPS-хостинге.
- Для запуска сайта не нужны Node.js, npm, package.json, сборка или backend-сервер.
- firebase.json оставлен только для конфигурации Firestore; он не запускает Node.js.
- Проверка файлов не заменяет тестирование OAuth, Firebase и внешних API в вашем
  собственном Firebase-проекте.


АДМИН-ПАНЕЛЬ V17.1
-------------------
Админ-панель видна только при входе в Firebase Authentication с killedofficialbd@gmail.com.
Проверка выполняется по email claim подписанного Firebase ID token; смена имени или
email в локальном профиле не выдаёт права администратора.

Перед использованием откройте Firebase Console → Firestore Database → Rules и
опубликуйте содержимое rules.txt из этого архива. Без публикации новых правил
админские операции будут отклоняться Firestore. Правила оставляют приватные users,
AI history и личные сообщения недоступными администратору. Список пользователей
строится по публичной коллекции publicProfiles (её существующая схема сохранена).

Приостановка пользователя создаёт owner-only документ wpAdminSuspensions/{uid}.
Новые операции Firestore такого аккаунта будут отклоняться правилами; вход в Firebase
Authentication полностью не отключается. Для полного блокирования Auth, отзыва токенов
и достоверного IP-логирования нужен серверный Firebase Admin SDK — он не входит в
статическую No-Node.js сборку.

IP-журнал: администратор может выбрать CSV access-логов своего хостинга. Файл
обрабатывается локально в браузере и не загружается в Firebase. Статическая страница
не собирает IP скрытно и не может надёжно связать IP с Firebase UID без backend.
V17.1.1: Исправлено скрытие значка основателя для не-владельцев. IP-адреса доступны в админ-панели только из реальных CSV-журналов хостинга; статический браузерный сайт не собирает IP других посетителей автоматически.
